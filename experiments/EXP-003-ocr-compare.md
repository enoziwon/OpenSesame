# EXP-003 OCR 엔진 비교 (사진 10장)

- 담당: 김민재
- 날짜: 2026-11-14 ~ 11-15
- 관련 이슈: #

## 가설
한국어 라벨 사진의 원재료명은 오픈소스 OCR로도 쓸 만큼 읽힌다. 안 되면 클라우드 OCR이 필요하다.

## 성공/실패 기준
- 글자 오류율(CER)이 낮을 것 (원재료 이름이 틀리면 분류가 틀린다)
- 괄호 구조가 정답과 같을 것 (괄호가 하나만 어긋나도 뒤 원재료가 전부 엉뚱한 하위 원재료가 된다)
- 시연·평가 규모에서 비용이 0원 수준일 것

## 데이터
- 공유 드라이브 `데이터 사진` 39장 중 10장. 저장소에는 올리지 않음.
- 상세페이지 이미지 4장(p01~p04), 실제 휴대폰 사진 6장(p05~p10).
  - 사진 조건: 빨간 배경·3단 괄호(p05), 용기 표면(p06), 곡면 컵·글자 잘림(p07), 구겨진 비닐 반사(p08), 저조도(p09), 광택 포장(p10)
- 정답: 원재료명 칸을 사진 보고 그대로 옮겨 적음 (띄어쓰기는 채점에서 무시). 항목명부터 끝의 '○○ 함유' 표시까지. **2차 검수 필요** (p08은 11/15 검수 완료).
- 비교 1: 모든 엔진에 원재료명 칸만 같은 좌표로 잘라서 입력.
- 비교 2(CLOVA만): 사진 전체를 넣고 `src/ocr/clova.py`가 원재료명 칸을 자동으로 찾음.
- **p08 수정 (11/15)**: 처음 측정 때 p08의 잘라 낸 칸과 정답이 면 원료(비타민B2)까지만이라 스프류 7줄과 함유 표시가 빠져 있었다.
  잘라 낸 칸을 함유 표시까지 넓히고(기울어진 함유 줄 아래의 포장재질 칸은 흰색으로 지움) 정답에 스프류·함유 표시를 추가했다.
  CLOVA·Google만 p08을 다시 측정했다. Tesseract·EasyOCR의 p08 값(†)은 처음 잘라 낸 칸·정답 기준 그대로다.

## 결과 (비교 2: CLOVA, 사진 전체 입력 → 원재료명 칸 자동 추출)
- 10장 모두 CER 0~6.6% (p01, p03, p04, p05, p06, p09 = 0%), 전체 1.9%
  - p08 3.2%: 남은 오류는 CLOVA가 글자를 잘못 읽은 것(`침맛`, `미늘`, `폴리인산나트름` 등)
- 값이 바뀐 과정
  - 처음: 전체 13.6%, p08 121.8%. 자동 추출은 스프류까지 뽑았는데 정답이 면 원료만이라 틀린 것으로 채점됐다.
  - p08 정답 수정 후: 전체 8.4%, p08 29.1%. 기울어진 아래쪽 두 줄과 함유 표시를 놓치고 `로스팅조`에서 추출이 멈췄다.
  - `clova.py` 수정 후(11/15): 전체 1.9%, p08 3.2%. 다른 9장의 추출 결과는 그대로다.
- '같은 제조시설'/'혼입 가능' 문장도 따로 추출됨 (p01~p04, p06)

## 오류 사례
1. Google p10: 줄 앞 테두리를 `[`, `(`로 읽음 → `[정제수, ...` 없는 괄호가 생김 → 뒤 원재료가 전부 하위 원재료로 묶임
2. Google p03: `유청단백분말(미` / `(국산)` 줄바꿈에서 `(`를 하나 더 만듦
3. CLOVA p02: `옥수수전분{옥수수:외국산(...)}`의 `{`를 `(`로 읽음 → 파서를 '괄호 종류 무관, 깊이만'으로 바꿔 해결
4. CLOVA p06: `고춧가루[건고추(중국산)]`의 `[`를 `(`로 읽음 → 같은 방식으로 해결
5. CLOVA p08: 구겨진 비닐에서 줄 순서가 섞임 (글자는 대부분 맞음, 기울어진 줄 하나가 맨 뒤로 감) → 사진을 다시 찍도록 안내하는 것이 현실적
6. Tesseract: 글자마다 띄어 쓰고(`소 맥 분`) 곡면·반사에서 다른 글자를 만들어 냄
7. 사진 전체 입력에서 옆 칸(영양정보·주소·주의사항)이 섞이던 문제 → CLOVA의 줄 단위(lineBreak) + 표의 항목명 칸 위치로 해결
8. 측정 실수: p08의 잘라 낸 칸과 정답이 원재료명 칸의 일부(면 원료)만 담고 있었음 → 11/15 수정. 다른 9장도 정답 범위가 같은지 2차 검수 때 확인
9. 비교 2 p08: 원재료명 칸 자동 추출이 기울어진 아래쪽 줄에서 멈춤 → 11/15 `src/ocr/clova.py` 수정
   - 원인 1: 오른쪽 옆 칸의 글머리표 조각(`·마`, `·소`)이 칸 경계에 걸쳐 원재료명 줄로 잡혔고, '·' 안내문으로 보고 멈춤 → 칸 밖으로 삐져나온 조각은 제외
   - 원인 2: 기울어져 위아래 줄 상자가 겹치면 같은 행으로 묶여 순서가 바뀔 수 있음 → 가로로 포개진 줄은 다른 행으로 봄
   - 원인 3: 오른쪽에 따로 있는 `밀, 대두,`가 앞 줄 끝 `건미역`에 붙음 → 칸 왼쪽 끝에서 시작하지 않는 줄은 띄어서 이음

## 결론
- 가설은 맞았나: 아니다. 오픈소스는 휴대폰 사진에서 글자의 절반 이상을 틀려 쓸 수 없다.
- 선택: **CLOVA OCR** (`OPENSESAME_OCR=clova`). 글자 정확도는 Google이 더 높지만, 괄호 트리가 파이프라인의 핵심이라 괄호 깊이를 10/10 지킨 CLOVA를 쓴다 (Google 6/10).
- 예비: Google Vision. CLOVA 무료가 월 100건이라 평가 데이터 대량 처리에는 Google(월 1,000건)이 낫다. 엔진 클래스만 추가하면 교체 가능.
- 다음 할 일: 나머지 9장 정답 2차 검수, 사진 수를 늘려 재측정(자동 추출 수정이 10장에 맞춰진 것은 아닌지 확인), p08 같은 사진은 '다시 찍기' 안내 기준 정하기.
