# 최종본 (src/final)

라벨 글자를 미국 9개 알레르기 판정으로 바꾸는 파이프라인이다. LLM을 부르지 않고 파서, 원재료 사전, 표시란 규칙만 쓴다.
팀 1차(`src/pipeline.py` + LLM 분류기)와 같은 응답 형식을 내므로 프런트엔드는 서버 주소만 바꾸면 그대로 붙는다.
같은 글자를 넣으면 늘 같은 결과가 나오고, 판정마다 근거 원재료와 이유 문장(영어·한국어)을 함께 준다.

## 흐름

| 단계 | 모듈 | 하는 일 |
|---|---|---|
| 2 | `src/ocr` (팀) | 사진에서 글자를 읽는다. 최종본도 팀 것을 그대로 쓴다 |
| 3·4 | `parser/` | 글자를 원재료명, 알레르기 표시란, 같은 시설 문구로 나누고 겹괄호를 원재료 나무로 푼다 |
| 5 | `lexicon/` | 원재료 이름 하나가 무엇에서 왔는지 찾는다. 정확 일치 사전과 키워드 규칙 |
| 6 | `verdict.py` | 원재료마다 근거를 모으고 한국 표시란과 맞춰 알레르기마다 확인됨·추정·판정 불가를 정한다 |
| 응답 | `pipeline.py`, `response.py` | 팀 형식에 근거 종류, 영어 이름, 이유 문장을 더해 돌려준다 |
| 서버 | `app.py` | `/health`, `/analyze`(사진), `/analyze-text`(글자) |
| 평가 | `eval/` | 정답 파일과 응답 파일을 받아 지표와 보고서를 낸다 |

판정 기준은 정답지 가이드 v1.1과 같다(`docs/09_gold_guide.md`). 사전의 만든 방법과 근거는 `lexicon/README.md`에 있다.

## 써 보기

```bash
pip install -r requirements.txt

# 글자 하나를 판정해 표와 JSON으로 본다
python -m src.final "원재료명: 소맥분(밀), 혼합조미분말, 참기름, 대두유 / 밀, 대두 함유"
python -m src.final "간장, 설탕, 양념분말" --declaration "대두, 밀 함유"     # 원재료명과 표시란을 따로 줄 때

# 서버
uvicorn src.final.app:app --port 8001
curl -s localhost:8001/analyze-text -H 'content-type: application/json' \
     -d '{"ingredients": "간장, 설탕, 양념분말", "declaration": "대두, 밀 함유"}'
```

프런트엔드는 `VITE_API_BASE_URL=http://localhost:8001`로 띄우면 최종본 서버를 본다. `/analyze`의 요청 형식(사진 하나, 필드 이름 `file`)은 팀 서버와 같다.
팀 OCR이 아직 가짜(mock)라 `/analyze`는 지금 고정된 글자를 판정한다. 글자를 직접 넣는 `/analyze-text`는 OCR 없이 돈다.

코드에서 쓸 때:

```python
from src.final.pipeline import analyze_text, analyze_fields
res = analyze_text("원재료명: 간장, 설탕 / 대두, 밀 함유")      # 사진에서 읽은 글자 전체
res = analyze_fields("간장, 설탕", "대두, 밀 함유")             # 원재료명과 표시란이 따로 있을 때
res.allergens[0].verdict, res.allergens[0].evidence_ingredient, res.allergens[0].reason_en
```

팀 파이프라인에 분류기만 바꿔 끼울 수도 있다(`FinalClassifier`). 다만 이 경우 원재료 이름 하나씩만 보므로 표시란 규칙과 괄호 속 하위 원료 규칙은 쓰지 못한다.

## 팀 1차와 다른 점

| | 1차 (LLM 분류기) | 최종본 |
|---|---|---|
| 원재료 판정 | LLM이 이름마다 답한다 | 사전에서 찾고, 없으면 키워드 규칙, 그래도 없으면 모르는 이름으로 남긴다 |
| 같은 입력의 결과 | 실행마다 달라질 수 있다 (EXP-003: 17개 중 2개가 3번 실행에서 갈림) | 늘 같다 |
| 한국 표시란 | 쓰지 않는다 | 근거로 쓴다. 표시란에 있으면 확인됨, 표시 의무가 있는데 없으면 추정을 지운다 |
| 괄호 속 하위 원료 | 부모 이름과 따로 판정한다 | 하위 원료가 적혀 있으면 그것으로 판단하고 부모 이름의 추정은 버린다 |
| 속을 알 수 없는 원료 | LLM 판단 | 양념·국물 계열만, 한국 표시 의무 밖인 생선과 참깨에만 판정 불가를 단다 |
| 정제 대두유 | LLM 판단 | 세지 않고 참고(notes)에 US-OIL로 적는다 |
| 속도와 비용 | 호출당 수 초, 과금 | 제품당 1ms 안팎, 과금 없음 |

EXP-003에서 문제가 된 네 가지는 최종본에서 이렇게 나온다: 카제인나트륨은 milk 확인됨, 새우맛분말은 crustacean 추정,
식물성유지(팜유)는 대두 근거가 아님, 혼합조미분말[멸치분말, …]은 괄호 속 멸치분말로 fish 확인됨.

## 응답에서 더한 칸

팀 형식(`src/common/schema.py`)의 칸은 뜻을 바꾸지 않았다. 팀 `AnalyzeResponse`로 읽어도 그대로 통과한다.

| 칸 | 내용 |
|---|---|
| `allergens[].basis` | 판정의 근거 종류. `INGREDIENT` 원재료에 확정 근거, `KR-DECL` 표시란, `R1-1` 표시란의 대두가 유지 때문일 수 있음, `LIKELY` 대개 들어가는 원료, `POSSIBLE` 들어가기도 하는 원료, `OPAQUE` 속 모를 양념·국물 원료, `COMPOUND` 속 모를 섞은 원료(표시란을 못 읽었을 때만) |
| `allergens[].species` | 종까지 알 때 영어 이름. 예: `["anchovy"]` |
| `allergens[].evidence_en` | 근거 원재료의 영어 이름. 사전에 없으면 null |
| `allergens[].reason_en`, `reason_ko` | 미국 사용자에게 보여 줄 한 문장과 그 한국어 |
| `declaration_text`, `declared` | 읽은 한국 알레르기 표시란 원문과 낱말. 못 찾으면 null과 빈 목록 |
| `notes` | 판정에 쓰지 않은 참고. US-OIL(세지 않은 정제유), 표시란 누락 의심, 한·미 차이, 같은 시설 문구 |
| `ingredients[].group` | 면·스프처럼 구성품을 묶는 머리말이면 true |

`warnings`가 비어 있지 않으면 결과를 단정하면 안 된다. 원재료를 읽지 못했거나 알레르기 표시란을 찾지 못한 경우다.

## 판정 규칙 한눈에

1. 원재료마다 사전에서 근거를 모은다. 등급은 확정(C), 추정(I), 가능(P)이고, 정제 대두유(R)와 종류 모를 유지(F)는 따로 둔다.
2. 괄호로 하위 원료가 적힌 원료는 하위 원료로 판단한다. 부모 이름에서는 확정 근거만 남긴다.
3. 한국 표시란을 읽는다. 우유·달걀·밀·대두·땅콩은 표시란이 전부 덮고, 생선은 고등어, 갑각류는 게·새우, 견과류는 호두·잣만 덮는다. 참깨는 덮지 않는다.
4. 알레르기마다 확정 근거가 있으면 확인됨, 표시란에 있으면 확인됨(대두는 유지 때문일 수 있어 따로 본다), 추정 근거가 남으면 추정,
   가능 근거나 속 모를 양념·국물 원료가 남으면 판정 불가다. 표시란이 덮는 알레르기인데 표시란에 없으면 추정과 가능은 지운다.
5. 아무 근거도 없으면 목록에 넣지 않는다. 화면은 이것을 안전하다고 보여 주면 안 된다.

## 확인한 것과 한계

- 테스트는 `python -m pytest -q`로 돈다. Python 3.9와 3.12에서 확인했다.
- 평가 기준과 결과는 `experiments/EXP-004-final-pipeline-criteria.md`에 있다. 기준은 결과를 보기 전에 적었다.
- 사전과 규칙은 HACCP 포장지 표기 공개 자료로 만들었다. 그 자료에 없는 제품, 수입 식품, 손글씨나 흐린 사진에서는 성능이 떨어질 수 있다.
- 사전에 없는 상표 이름과 처음 보는 원재료는 모르는 이름으로 남고, `undecidable_ingredients`에 적힌다. 알레르기를 지어내지 않는 대신 놓칠 수 있다.
- 판정은 라벨에 적힌 글자만 본다. 같은 시설 문구는 판정에 쓰지 않고 참고로만 옮긴다.
- 연구·수업용이다. 알레르기 판단에 단독으로 쓰면 안 된다.

## AI 사용 기록

이 폴더의 코드와 사전은 Claude Code로 만들었다. 설계 판단과 검토는 Claude Fable 5.2가, 판정 엔진·채점 코드·파서 수정의 구현은 Claude Opus 5.5 에이전트가 맡았다.
판정 기준(가이드 v1.1)의 새 결정은 Claude가 자료를 세어 정한 제안이고 팀 확인 전이다. 사람 검수 범위는 `lexicon/README.md`와 EXP-004에 적었다.
