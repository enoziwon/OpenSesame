# 02. 아키텍처와 기술 스택 — 초안

## 파이프라인

```
📷 라벨 사진
   ↓
🔤 OCR  (엔진은 2주 내 비교 후 선택)
   ↓
🧹 원재료 파서  (중첩 괄호 → 트리, 구분자·함량·원산지 정리)
   ↓
🧠 알레르겐 추론  (원재료 스팬 → 본국 기준 알레르겐)
   ↓
⚖️ 한국 표시 목록과 대조  (표시란에 이미 있는 항목은 제외)
   ↓
📱 출력: 확정 / 추론가능 / 판정불가 + 근거 원재료
```

오프라인(학습·평가)이 본체이고, 앱 추론은 같은 파서·모델을 재사용하는 데모다.

## 기술 스택 (후보 — 확정 아님)

| 영역 | 후보 | 비고 |
|---|---|---|
| OCR | 클라우드 OCR 1~2종 + 오픈소스 1종 | 사진 10장으로 비교 후 결정 |
| LLM 베이스라인 | 멀티모달 LLM 1~2종 | 프롬프트 통일 필수 |
| 모델 | KLUE-RoBERTa / KoELECTRA 계열 + 자모 단위 입력 병행 | OCR 오타 대응 |
| 프레임워크 | Python, PyTorch, Hugging Face Transformers | |
| 데이터 | 식약처 품목제조보고(원재료) API, 직접 촬영 사진 | 공공데이터포털 |
| 앱(데모) | 웹 또는 모바일 중 담당자가 선택 | 서버·로그인 없음 |
| 협업 | GitHub, Discord, 공유 드라이브 | |

## 평가 설계

- **Seen / Unseen 분할**: 원재료명 기준으로 나눈다.
- **2×2 실험**: (일반 학습 / 노이즈 증강 학습) × (깨끗한 텍스트 / 실제 OCR 텍스트)
- **지표**: 누락 가중 재현율, 오경보율, 판정불가 적절성. 정확도는 보조.
- **베이스라인**: 사전 매칭, LLM zero-shot.
- **gold**: 법령 조항 근거로 사람이 검수. 예외 조항(정제유 등)까지 반영.

## 범위 밖

- 식당·비포장 식품, 교차오염, 제조 공정 판단
- 다국어 UI (출력은 영어 템플릿 하나)
- 로그인, 서버 DB, 이력 관리
