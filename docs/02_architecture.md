# 02. 아키텍처와 기술 스택 — 초안

## 사용자 흐름 (제품)

```
[사전] 관광객이 미국 9개 항목 중 본인의 알레르기 선택
   ↓
📷 라벨 촬영 (원재료명)
   ↓
경고 화면: 선택한 항목 기준 확인됨 / 추정 / 판정 불가 + 근거 원재료
```

## 파이프라인

```
🧾 알레르기 프로필 (선택한 항목, 세션에서만 유지)
📷 라벨 사진
   ↓
🔤 OCR  (엔진은 2주 내 비교 후 선택)
   ↓
🧹 원재료 파서  (중첩 괄호 → 트리, 구분자·함량·원산지 정리)
   ↓
🧠 알레르겐 추론  (원재료 스팬 → 미국 9개 알레르겐)
   ↓
⚖️ 프로필 대조  (선택한 항목만 경고. 9개 밖은 확인하지 않음을 명시)
   ↓
📱 출력(영어): 확인됨 / 추정 / 판정 불가 + 근거 원재료
```

한국 표시란과의 비교는 선택 기능이다. 필수 경로가 아니다.

## 제품 구성

- 웹앱 한 화면: 프로필 선택 → 사진 업로드 → 결과.
- 공개 URL로 배포해 누구나 열어볼 수 있게 한다.
- 로그인, DB, 이력 저장은 없다. 프로필은 브라우저 세션에서만 유지한다.
- 첫 버전은 분류기를 LLM으로 두고 끝까지 돌린다. 이후 파서·모델로 교체하며 성능 차이를 측정한다.

## 기술 스택 (후보 — 확정 아님)

| 영역 | 후보 | 비고 |
|---|---|---|
| OCR | 클라우드 OCR 1~2종 + 오픈소스 1종 | 사진 10장으로 비교 후 결정 |
| LLM 베이스라인 | 멀티모달 LLM 1~2종 | 프롬프트 통일 필수 |
| 모델 | KLUE-RoBERTa / KoELECTRA 계열 + 자모 단위 입력 병행 | OCR 오타 대응 |
| 프레임워크 | Python, PyTorch, Hugging Face Transformers | |
| 데이터 | 식약처 품목제조보고(원재료) API, 직접 촬영 사진 | 공공데이터포털 |
| 제품(웹앱) | 담당자가 선택 (경량 Python 웹 프레임워크 후보) | 서버 저장·로그인 없음 |
| 협업 | GitHub, Discord, 공유 드라이브 | |

## 평가 설계

- **Seen / Unseen 분할**: 원재료명 기준으로 나눈다.
- **프로필 시뮬레이션**: 가상 프로필(9개 중 임의 조합)로 경고 결과를 평가한다. 실제 사람의 정보는 쓰지 않는다.
- **입력 조건**: 깨끗한 텍스트 / 실제 OCR 텍스트. 학습은 일반 / 노이즈 증강을 비교한다.
- **지표**: 누락 가중 재현율, 오경보율, 판정 불가 적절성. 정확도는 보조.
- **베이스라인**: 사전 매칭, LLM zero-shot.
- **gold**: 법령 조항 근거로 사람이 검수. 예외 조항(정제유 등)까지 반영.

## 범위 밖

- 식당·비포장 식품, 교차오염, 제조 공정 판단
- 미국 9개 밖의 알레르기, 다른 나라 기준
- 다국어 UI (출력은 영어 템플릿 하나)
- 로그인, 서버 DB, 이력 관리
